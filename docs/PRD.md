# TelegramFlow — Product Requirements Document (PRD)

## 1. Общие сведения

| Параметр | Значение |
| :--- | :--- |
| **Продукт** | TelegramFlow |
| **Цель** | Веб-платформа автоматизации продвижения в Telegram с автоматическим управлением прокси, сессиями и лимитами |
| **Позиционирование** | Интеллект корпоративного уровня по цене обычного софта, запуск в 3 клика («Результат без настройки») |

### 1.1. Стек технологий

| Слой | Технологии |
| :--- | :--- |
| **Frontend** | Next.js, TailwindCSS |
| **Backend API** | FastAPI (Python), REST + WebSockets |
| **БД** | PostgreSQL (основные данные), Redis (очереди Celery) |
| **Telegram Engine** | Python, **Hydrogram** (Pyrogram-compatible, PyPI `hydrogram==0.2.0`) |
| **LLM** | **DeepSeek API** по умолчанию; переключение на OpenAI через универсальный адаптер |
| **Интеграции** | DeepSeek / OpenAI (OpenAI-compatible SDK), Telegram `@CryptoBot` API |

### 1.2. Структура монорепозитория

```text
TELEFLOW/
├── docs/                 # Документация (PRD, спецификации)
├── frontend/             # Next.js + TailwindCSS
├── backend/              # FastAPI REST + WebSockets
├── workers/              # Celery workers (Telegram Engine, LLM, парсинг)
├── docker-compose.yml    # PostgreSQL, Redis, Backend, Workers
└── .env.example          # Шаблон переменных окружения
```

## 2. Модули системы

### 2.1. Модуль автоматической инфраструктуры (Backend)

**Назначение:** Полное исключение участия пользователя в покупке и настройке прокси/сессий.

**Функционал:**
- Привязка внутренних прокси (IPv4 / SOCKS5) к сессионным аккаунтам (`.session`).
- Автоматический мониторинг статуса аккаунтов (`active`, `flood_wait`, `banned`).
- Ротация заблокированных аккаунтов на резервные из внутреннего пула без остановки кампании.

### 2.2. Пользовательский интерфейс (Frontend)

Три последовательных шага настройки:

1. **Модуль обучения ИИ**
   - Форма ввода URL сайта или загрузки файлов (PDF/TXT).
   - Парсер: извлечение текста, очистка HTML, сохранение структуры знаний.

2. **Модуль определения аудитории**
   - Ключевые слова или ссылки на целевые Telegram-каналы/чаты.
   - Автоматический сбор и валидация целевых площадок.

3. **Модуль запуска и аналитики**
   - Настройка коммерческого предложения / цели кампании.
   - Запуск кампании в один клик.
   - Дашборд: отправленные сообщения, активные диалоги, статус Smart-Shield.

```text
+-----------------------------------------------------------------------+
| 1. Источник знаний      2. Целевая аудитория      3. Запуск и метрики |
| [ URL сайта / PDF ]  -> [ Ссылки на группы ]   -> [ Оффер + Старт ]   |
+-----------------------------------------------------------------------+
```

**UX-правила (из рыночной стратегии):**
- В UI нет терминов «SOCKS5», «TData», «FloodWait», «API ID», «API Hash».
- Пользователь не загружает `.session` и не настраивает прокси.

### 2.3. Исполнительный модуль (Worker Cluster)

**Обработка Telegram API:**
- Асинхронный прослушиватель входящих событий.
- Имитация человека: `send_chat_action` («печатает...»), случайные задержки 30–120 сек.

**Smart-Shield:**
- Динамический контроль суточных лимитов на аккаунт.
- Перехват `FloodWait`: пауза задачи или замена аккаунта.

### 2.4. Модуль нейросетевой генерации (LLM Router)

- Контекст: текущее сообщение + 3–5 предшествующих.
- Системный промпт: текст сайта/документа + правила поведения (без агрессивной рекламы, ответы по существу).
- Фильтрация ответа перед отправкой в Telegram.

### 2.5. Модуль биллинга

- Подписка за период + лимитированный баланс токенов генерации.
- Счета и проверка оплаты через API `@CryptoBot`.
- Блокировка workers при исчерпании кредитов или окончании подписки.

**Ориентир монетизации (стратегия):**
- Подписка ~$49/мес (инфраструктура: аккаунты, прокси, базовый парсинг).
- Add-on AI-Credits (оплата за генерации / осмысленные диалоги).

---

## 3. Критерии приемки (Definition of Done)

1. UI не содержит полей для прокси, API ID, API Hash и загрузки файлов сессий.
2. Запуск кампании строго в 3 шага.
3. Backend изолирует заблокированный аккаунт и продолжает кампанию на резервном.
4. Парсинг сайта по URL ≤ 60 секунд с момента ввода ссылки.

## 4. Зафиксированные решения

| Параметр | Решение | Примечание |
| :--- | :--- | :--- |
| Telegram Engine | **Hydrogram** | Async MTProto; оригинальный Pyrogram архивен — только официальный PyPI, без сторонних «форков» |
| LLM | **DeepSeek** (default) | Совместимость с OpenAI SDK; адаптер `LLM_PROVIDER=deepseek\|openai` без смены логики воркеров |
| API-ключи (LLM, CryptoBot, Telegram API) | Отсутствуют | Заполнить в `.env` при появлении |
| Тестовые прокси и аккаунты | Отсутствуют | Пул инфраструктуры — внутренний, без UI для пользователя |

### 4.1. LLM Router — адаптер

- Единый интерфейс чат-комплишена (OpenAI-compatible).
- DeepSeek: `base_url` + `DEEPSEEK_API_KEY`.
- OpenAI: стандартный endpoint + `OPENAI_API_KEY`.
- Воркеры вызывают только адаптер; смена провайдера — через `LLM_PROVIDER`.
